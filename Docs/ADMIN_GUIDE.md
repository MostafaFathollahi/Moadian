# راهنمای مدیر سامانه

راه‌اندازی، پیکربندی، مدیریت کاربران و نگهداری.

## ۱. معماری در یک نگاه

| بخش | نقش |
|---|---|
| **بک‌اند** (Python/FastAPI) | امضا، رمزگذاری، ارسال، اعتبارسنجی، ذخیره‌سازی |
| **رابط کاربری** (React) | فرم‌ها و گزارش‌ها؛ هیچ عملیات رمزنگاری در مرورگر انجام نمی‌شود |
| **گواهی و کلید امضا** | فایل‌هایی روی سرور که تنها بک‌اند می‌خواند |

> **کلید خصوصی هرگز از مرورگر عبور نمی‌کند.** نه بارگذاری می‌شود، نه نمایش داده
> می‌شود، و نه هیچ نقطه‌ای از API آن را می‌پذیرد یا برمی‌گرداند. مسیر فایل‌ها تنها
> از متغیرهای محیطی سرور خوانده می‌شود.

## ۲. راه‌اندازی

### ۲-۱. آماده‌سازی گواهی و کلید

فایل‌ها را مستقیماً روی سرور قرار دهید (scp، secret مانت‌شده، ابزار پیکربندی) و
دسترسی کلید را محدود کنید:

```bash
mkdir -p /secure/moadian
cp cert.crt key.pem /secure/moadian/
chmod 600 /secure/moadian/key.pem
```

توصیه می‌شود کلید را به صورت رمزگذاری‌شده نگه دارید. در این حالت کلید هم روی دیسک
رمز است و هم از برنامه عبور نمی‌کند:

```bash
openssl pkcs8 -topk8 -in key.pem -out key.enc.pem
```

> **اگر مرکز صدور گواهی فایل `.pfx` تحویل داده باشد:** این برنامه به آن نیازی
> ندارد و آن را نمی‌پذیرد. `.pfx` صرفاً بسته‌بندیِ همان گواهی و کلید در یک فایل
> رمزگذاری‌شده است و برای ویندوز، IIS و دات‌نت کاربرد دارد. اگر در راهنمای مرکز
> صدور، مرحله‌ای برای ساخت `.pfx` از `.crt` و کلید خصوصی دیده‌اید، آن مرحله را
> رد کنید — همان دو فایل اصلی همان چیزی است که لازم داریم. اگر فقط `.pfx` دارید:
>
> ```bash
> openssl pkcs12 -in bundle.pfx -clcerts -nokeys -out cert.crt -passin pass:YOURPASS
> openssl pkcs12 -in bundle.pfx -nocerts        -out key.pem  -passin pass:YOURPASS -passout pass:NEWPASS
> chmod 600 key.pem
> ```
>
> (با `-nodes` کلید بدون رمز استخراج می‌شود؛ بدون آن کلید رمزگذاری‌شده می‌ماند و
> باید `MOADIAN_KEY_PASSPHRASE` را تنظیم کنید — روش امن‌تر همین است.)

### ۲-۲. متغیرهای محیطی

از `backend/.env.example` نسخه بگیرید و مقادیر را تنظیم کنید:

```bash
# گواهی و کلید امضا — پیش‌فرض هر دو محیط
MOADIAN_CERTIFICATE_PATH=/secure/moadian/cert.crt
MOADIAN_PRIVATE_KEY_PATH=/secure/moadian/key.pem

# در صورت نیاز، برای هر محیط جداگانه. زمانی لازم می‌شود که گواهی معتبر تنها
# برای محیط عملیاتی صادر شده و محیط آزمایشی هنوز با گواهی آزمایشی کار می‌کند.
# MOADIAN_SANDBOX_CERTIFICATE_PATH=...
# MOADIAN_PRODUCTION_CERTIFICATE_PATH=...

# در صورت رمزگذاری‌شده بودن کلید
# MOADIAN_KEY_PASSPHRASE=...

# رمز باز کردن مخزن رمزگذاری‌شده حافظه‌های مالیاتی — الزامی
MOADIAN_MASTER_PASSPHRASE=...

# امضای توکن نشست کاربران این برنامه (ربطی به کلید امضای مالیاتی ندارد)
MOADIAN_APP_SECRET=<۳۲ بایت تصادفی>
MOADIAN_TOKEN_TTL_HOURS=12

# کاربران اولیه — پس از نخستین اجرا گذرواژه را تغییر دهید
MOADIAN_SEED_USERS=admin:admin1234:admin
```

> اگر `MOADIAN_APP_SECRET` تنظیم نشود، در هر بار اجرا یک مقدار تصادفی ساخته
> می‌شود. این امن است ولی با هر ری‌استارت همه کاربران از سامانه خارج می‌شوند.

### ۲-۳. اجرا

```bash
# بک‌اند
cd backend
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
.venv/bin/uvicorn moadian.api.app:app --host 127.0.0.1 --port 8000

# رابط کاربری
cd frontend
npm install
npm run dev          # توسعه: http://localhost:5173
npm run build        # تولید: پوشه dist را با یک وب‌سرور سرو کنید
```

> API قادر است به نام شما صورتحساب امضا و ارسال کند. آن را روی `127.0.0.1` نگه
> دارید یا پشت یک پراکسی با احراز هویت قرار دهید. مدل چندمستاجری وجود ندارد.

## ۳. پیش‌از‌پرواز: آزمون گواهی واقعی

پیش از صدور نخستین صورتحساب، این دستور را اجرا کنید. هیچ صورتحسابی ارسال
نمی‌کند و هیچ چیزی را تغییر نمی‌دهد:

```bash
cd backend
.venv/bin/python tools/preflight.py --memory-id <شناسه یکتای شما>
```

سه مرحله را به ترتیب بررسی می‌کند و در نخستین شکست می‌ایستد، چون مرحله بعد بدون
مرحله قبل قابل تفسیر نیست:

| مرحله | چه چیزی را می‌سنجد |
|---|---|
| **۱ — محلی** | گواهی و کلید خوانده می‌شوند، با هم جفت‌اند، کلید ۲۰۴۸ بیتی است، گواهی خودامضا نیست، و کد ملی داخل آن چیست. بدون شبکه. |
| **۲ — دسترسی** | `GET /nonce` که به گواهی نیاز ندارد. این مرحله «شبکه به سازمان نمی‌رسد» را از «گواهی رد شد» جدا می‌کند — دو خطایی که در غیر این صورت یکسان به نظر می‌رسند. |
| **۳ — پذیرش** | نخستین فراخوانی احراز‌هویت‌شده. اینجاست که سازمان برای اولین بار گواهی، زنجیره آن و دسترسی آن هویت به شناسه یکتای شما را قضاوت می‌کند. |

اگر مرحله ۳ شکست خورد، معمولاً یکی از این سه است:

- گواهی هنوز در **کارپوشه** برای این حافظه مالیاتی بارگذاری نشده است
  (بند ۲ سند فنی: عضویت و ثبت‌نام ← بارگذاری کلید عمومی/گواهی امضاء)؛
- کد ملی داخل گواهی برای این شناسه یکتا دسترسی ارسال ندارد؛
- این شناسه یکتا متعلق به محیط دیگری است.

## ۴. بررسی سلامت پیکربندی

در «تنظیمات» بخش **گواهی امضا و کلید خصوصی** وضعیت هر محیط را نشان می‌دهد:

- آیا مسیر تنظیم شده است
- آیا فایل موجود است
- سطح دسترسی فایل، و اینکه آیا کلید برای گروه/دیگران خواندنی است
- آیا کلید رمزگذاری‌شده است

هرگز محتوای فایل‌ها خوانده یا نمایش داده نمی‌شود.

## ۵. تعریف حافظه مالیاتی

برای هر شناسه یکتای حافظه مالیاتی یک ردیف بسازید:

| فیلد | توضیح |
|---|---|
| نام نمایشی | برای تشخیص در فهرست |
| شناسه یکتا | ۶ نویسه، حروف بزرگ و رقم |
| محیط | آزمایشی یا عملیاتی |
| شماره اقتصادی | اختیاری |

> شناسه یکتای حافظه مالیاتی برای هر محیط جداگانه صادر می‌شود و بین محیط‌ها قابل
> انتقال نیست. به همین دلیل محیط بخشی از خود حافظه است و به‌صورت مستقل قابل تغییر
> نیست — این جلوگیری می‌کند از اینکه هویت آزمایشی به محیط عملیاتی ارسال شود.

پس از ساخت، **آزمون اتصال** را بزنید. نتیجه دو بخش دارد:

- **دریافت چالش** — شبکه و مسیر درست است. به گواهی نیازی ندارد.
- **احراز هویت** — گواهی امضا پذیرفته شده است.

اگر بخش نخست موفق و بخش دوم ناموفق باشد، مشکل از گواهی است نه از شبکه. گواهی
خودامضا هرگز پذیرفته نمی‌شود: سازمان زنجیره گواهی را از طریق OCSP و CRL بررسی
می‌کند و گواهی باید از یکی از مراکز میانی معتبر کشور صادر شده باشد.

همچنین **کد ملی داخل گواهی** (فیلد SERIALNUMBER) باید با شماره اقتصادی فروشنده
صورتحساب بخواند، وگرنه سازمان خطای ۴۱۰۳ برمی‌گرداند. این مقدار در فهرست
حافظه‌ها نمایش داده می‌شود.

## ۶. مدیریت کاربران

دو نقش وجود دارد:

| نقش | دسترسی |
|---|---|
| **کاربر** | صدور، اعتبارسنجی، ارسال، پیگیری، خریداران، کالاها |
| **مدیر** | همه موارد بالا، به‌علاوه تنظیمات، حافظه‌های مالیاتی و مدیریت کاربران |

قواعدی که سامانه اعمال می‌کند:

- گذرواژه دست‌کم ۸ نویسه.
- نام کاربری ۳ تا ۶۴ نویسه از حروف و ارقام انگلیسی و `. _ -`.
- **آخرین مدیر فعال** قابل حذف، غیرفعال‌سازی یا تنزل نقش نیست.
- هیچ‌کس نمی‌تواند نقش یا فعال‌بودن حساب خودش را تغییر دهد.
- «حذف» کاربر در واقع **غیرفعال‌سازی** است؛ ردیف باقی می‌ماند چون پرسش‌های
  حسابرسی درباره «چه کسی این صورتحساب را فرستاد» بعد از حذف حساب هم مطرح می‌شوند.

### بستن نشست‌ها

- **خروج یک کاربر از همه دستگاه‌ها** — توکن‌های آن حساب باطل می‌شود.
- **خروج همه کاربران** — پس از استقرار نسخه جدید مفید است. نشست خودتان قطع
  نمی‌شود؛ توکن تازه‌ای دریافت می‌کنید.

تغییر گذرواژه (چه توسط خود کاربر و چه توسط مدیر) به‌طور خودکار نشست‌های قبلی آن
حساب را می‌بندد. غیرفعال‌کردن حساب نیز بلافاصله دسترسی را قطع می‌کند، نه در پایان
مهلت توکن.

## ۷. نگهداری

### پشتیبان‌گیری

| مسیر | محتوا | حساسیت |
|---|---|---|
| `instance/profiles.json` | حافظه‌های مالیاتی (رمزگذاری‌شده) | نیازمند رمز اصلی |
| `instance/records.sqlite` | صورتحساب‌ها، خریداران، کالاها | داده کاری |
| `instance/users.sqlite` | حساب‌های کاربری | هش گذرواژه |
| `instance/serial-<شناسه>` | شمارنده سریال هر حافظه | **بحرانی** |
| مسیر گواهی و کلید | هویت امضا | **بحرانی** |

> **شمارنده سریال را از دست ندهید.** شماره سریال بخشی از شماره منحصر به فرد
> مالیاتی است. اگر شمارنده به عقب برگردد، شماره‌های تکراری تولید می‌شوند و
> سازمان آن‌ها را رد می‌کند؛ هیچ درخواستی این را جبران نمی‌کند. اگر روزی سامانه را
> روی بیش از یک ماشین اجرا کردید، این شمارنده باید به یک منبع مشترک منتقل شود.

### به‌روزرسانی

پس از استقرار نسخه جدید، «خروج همه کاربران» را بزنید تا کسی با رابط کاربری قدیمی
به API جدید وصل نماند.

### آزمون‌ها

```bash
cd backend
.venv/bin/pytest -m "not live"      # آفلاین — بدون تماس با سازمان
.venv/bin/pytest -m live            # نیازمند دسترسی شبکه به سازمان
.venv/bin/python tools/check_connectivity.py   # بدون نیاز به گواهی
```

`check_connectivity.py` وضعیت DNS، TLS و پاسخ سرویس را برای هر دو محیط گزارش
می‌کند و نیازی به گواهی ندارد. اگر آدرس به محدوده `198.18.x.x` رسید، شبکه شما نام
`tax.gov.ir` را دستکاری می‌کند و مشکل از سرویس نیست.

## ۸. نکات فنی که ممکن است لازم شود

- **قواعد اعتبارسنجی** از جدول ۱ دستورالعمل سازمان به‌صورت خودکار استخراج شده و در
  `backend/src/moadian/rules/patterns.yaml` نگهداری می‌شود. این فایل تولیدشده است؛
  برای تغییر، ابزار `tools/extract_table1.py` را اجرا کنید.
- **گرد کردن مبالغ** هنوز قطعی نیست: مبالغ ریالی بدون اعشارند ولی نرخ مالیات دو
  رقم اعشار دارد، و دستورالعمل نحوه گرد کردن را نگفته است. فعلاً اختلاف یک ریال
  پذیرفته می‌شود.
- **مهلت انتظار پیش از استعلام** دست‌کم ده ثانیه است و سامانه آن را رعایت می‌کند.
- **حداکثر ۱۰۰۰ صورتحساب** در هر درخواست؛ دسته‌های بزرگ‌تر خودکار تقسیم می‌شوند.
